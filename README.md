# clipboard-sync：截图即入库（剪贴板 → 飞书多维表格）

用 **PixPin**（或任何"截图即复制到剪贴板"的工具）截一张图，图会在几秒内自动出现在
**飞书多维表格**里对应门店的对应屏位。不用另存为、不用拖拽、不用手动选列。

> 典型场景：采集网吧 / 电竞馆门店信息，每家店要存「店铺首页、设备与服务、座区、外设专区」
> 四类截图。手工做是每家店 4 次"另存为 + 上传 + 选单元格"。用这套工具是**一路截图，自动归位**。

---

## 一、整体链路

```
  PixPin 截图（Ctrl+C / Enter / 双击 复制）
          │
          ▼
  macOS 系统剪贴板  ──本工具每 120ms 轮询 changeCount──┐
          │                                          │
          ▼                                          ▼
   剪贴板内容分类                              clipboard.py
   ├─ 文本（店名）                             读 NSPasteboard
   │     └─► 写入「终端名称」列，锁定这一行 ◄─────────┘
   │           （优先填界面上最靠上的空白行，没有才新建）
   └─ 图片（截图）
         ├─ 落盘 tmp/，算内容指纹（去重）
         ├─ 本地 OCR（macOS Vision，离线，不上传任何第三方）
         ├─ 屏位判定：这是第几屏？
         ├─ 进待上传队列（落盘 queue.json，崩溃也不丢）
         └─ 线程池上传 → 飞书（先读该单元格现有附件，再追加写回）
                    │
                    ▼
         飞书多维表格：第一屏 / 第二屏 / 第三屏 / 第四屏 附件列
```

**关键点：整条链路里没有任何一步需要你手动指定"这张图放哪"。** 靠的是"文本建行 + 图片接着归位"这个约定。

## 二、工作原理（拆开讲）

### 1. 捕获：轮询剪贴板，不是监听剪贴板

macOS 没有可靠的剪贴板事件通知。程序每 120ms 读一次 `NSPasteboard` 的 `changeCount`，
变了才去取内容。开销可忽略，也不需要任何辅助功能权限。

### 2. 分类：文本 = 新的一家店，图片 = 这一家店的截图

- 读到**文本**（≤60 字）→ 认为是店名 → 写入「终端名称」列，**并把这一行锁定为"当前行"**。
- 读到**图片** → 认为属于"当前行" → 判屏位 → 上传。

所以正确操作顺序是：**先复制店名，再一路截图**。

如果先截图后复制店名（`fallback.require_text_first: true`），图片会先挂到 `pending/`，
等店名建好行之后**自动回灌**，不会丢。

### 3. 建行：严格按界面从上往下（并做了缓存）

`text.row_selection: auto` → 先找「终端名称 + 四个屏位全空」的空白行，找到就写它，找不到才新建。

> ⚠️ 这里踩过一个大坑：早期版本用飞书服务端 `filter` 筛空行，而**飞书一旦带 filter，
> 返回顺序就不再是界面顺序**，导致写入落到随机一行。现在改为：只用 `view_id` 翻页保序，
> 空行判断放在本地做。**所以 `feishu.view_id` 必须填**，否则顺序不保证。

> 🚀 另一个坑：单页上限其实可以开到 **500**，但旧代码写死 100，于是 365 行的表要翻 4 次页
> ≈ 12 秒 —— 这就是"收到店名后要等十几秒才见它建好行"的原因（创建行本身只要 3 秒）。
> 现在：单页取满 500 + **一次扫描攒一批空行缓存起来**，连续建行时取行耗时 **0ms**；
> 表里没空行时也会记住这个结论，30 秒内不再重复扫表。
> 实测：建行总耗时 **约 15s → 约 3s**。

### 4. OCR：本地 Vision，离线

调用 macOS 内置的 **Vision** 框架（`VNRecognizeTextRequest`），不联网、不调任何云 API、
截图内容不会离开你的电脑（上传到飞书除外，那是你的目标）。

常驻进程模式：OCR 模型只加载一次（首次约 15s，面板启动时后台预热），之后每张约 0.2s。

> ⚠️ `ocr.cpu_only` 必须保持 `false`。实测常驻进程强制走 CPU 会 **100% 返回空文本**
> （60 张全空，每张 0.01s 根本没识别）—— 这是"跑一会儿就开始未识别"的真正原因，
> 不是图的问题，也不是内存泄漏。

### 5. 屏位判定：关键词 + 顺序双保险

纯靠关键词分不开第二屏和第三屏（座区少的时候两屏长得一模一样），所以：

- **关键词规则**：第一屏（营业中 / 暂停营业…）、第四屏（外设专区 + 设备与服务）、
  第二屏（设备与服务 + 收起）、第三屏（设备与服务 + 座区）。
- **顺序规则（flow）**：命中「设备与服务」的页，**本行第 1 张 → 第二屏（并同时补一份到第三屏）**，
  之后每张 → 第三屏。
- **兜底守卫**：某张图 OCR 漏掉「设备与服务」时，先判断它像不像第四屏，
  不像就按序列续接，避免被"无条件兜底"塞进第四屏。

判定不出来屏位的图不会乱放，会存到 `unmatched/` 并在日志里标红，你能立刻发现。

### 6. 上传：队列 + 并发 + 重试

- 任务先落盘到 `queue.json`，**传完才出队** → 中途崩溃/强退，下次启动自动补传。
- 3 个线程并发上传，但**同一单元格串行**，防止互相覆盖。
- 上传前要读一次单元格现有附件（追加而不是覆盖）。**刚新建的行飞书索引还没生效**，
  立刻读会返回 `1254607 Data not ready` —— 现已自动退避重试 + 新行预置空附件缓存。
- 超过 900KB 的图自动压缩（长边 1600、JPEG 85），原图小于 900KB 不动。

### 7. 去重与撤回

- 内容指纹去重（文本按文字、图片按字节），连续重复自动跳过。
- 「撤回上一步」：删整行 / 清空字段 / 只删那一张图，并**同时取消还在排队和上传中的同内容任务**，
  队列里的待传任务也一并清除 —— 不会出现"撤回后图又冒出来"。

## 五、飞书侧配置（一次性）

### 1）创建应用并开权限

1. 打开 [飞书开放平台](https://open.feishu.cn/app) → **创建企业自建应用**。
2. 「权限管理」里开通：
   - `bitable:app`（查看、评论、编辑和管理多维表格）
   - `drive:file`（上传 / 下载素材）
3. **「版本管理与发布」→ 创建版本 → 申请发布**。
   ⚠️ 权限改完不发版本不生效 —— 这是最常见的漏点，会报 `99991672`。
4. 拿到 **App ID** 和 **App Secret**（凭证与基础信息页）。

### 2）把应用加进表格

打开你的多维表格 → 右上角「···」→ **添加文档应用** → 选刚建的应用 → 权限给 **可编辑**。

不加这一步会报 `1254005 / 1254006`。

### 3）拿三个 ID

多维表格 URL 长这样：

```
https://xxx.feishu.cn/base/<app_token>?table=<table_id>&view=<view_id>
```

| 配置項 | 从哪拿 | 必填 |
|---|---|---|
| `feishu.app_token` | `/base/` 后面那段 | ✅ |
| `feishu.table_id` | `?table=` 后面那段 | ✅ |
| `feishu.view_id` | `&view=` 后面那段 | ✅（**保序用，不填会写入随机行**） |

> 也可以直接在面板「设置」里**粘贴整个表格链接**，程序会自动解析出这三个值。
> `view_id` 大小写敏感。

### 4）表格字段

至少需要：

- 一个**文本列**：店名（默认列名「终端名称」）
- 四个**附件列**：第一屏 / 第二屏 / 第三屏 / 第四屏

列名不叫这个也行，在 `config.yaml` 的 `feishu.fields` 里映射一下即可
（左边是程序内部名，右边是你表里的列名或字段 ID）。

### 5）自检

面板上点 **「测试飞书连接」**，两项全绿就说明配好了。

## 六、PixPin 怎么配（这一步最容易踩坑）

推荐 PixPin 的原因是它**截图后可以直接进剪贴板**，正好对上本工具的入口。

### 必须做到：截图后图进了剪贴板

PixPin 截图后，用下面任意一种方式复制：

- `Ctrl + C`
- `Enter`
- **鼠标双击**选区
- 点工具栏的复制图标

也可以在 PixPin「设置 → 快捷键/动作」里把「**截图并复制**」绑到一个快捷键，一步到位。

### ⚠️ 一个必须避开的坑

PixPin「**配置 → 系统 → 剪贴板 → 复制图像为文件**」如果设成了 `PNG / JPG / WEBP` 等具体格式，
剪贴板里放的是**文件路径**而不是图像数据 —— 本工具读不到图，表现为"截了图但没反应"。

把这项设为 **「禁用」**（或「自动」）即可。

### 不用 PixPin 也行

- **macOS 自带截图**：`⌘⇧4` 默认存成桌面文件，**必须按住 Ctrl**（`⌘⇧Ctrl+4`）才会进剪贴板。
- **Snipaste / 微信截图 / CleanShot X** 等：只要设置成"截图后自动复制到剪贴板"都可以。

## 七、日常怎么用

1. 打开面板（或「剪贴板采集」App），确认在监听。
2. 在表格里**提前建好若干空白行**（想批量采集 15 家，就先建 15 行空行）——
   程序会**按界面从上往下依次**填入。
3. 复制店名文本（⌘C）→ 面板日志出现「店名 XXX → 写入空行」。
4. 一路截图。每张图 1~3 秒后出现在对应屏位。
5. 这家店截完，复制下一家店的店名 → 自动切到下一行。
6. 截错了 → 点「**撤回上一步**」，只删那一张，同单元格其余保留。

日志区会逐条打印每张图的判定依据，例如：

```
[18:08:27] [分屏] 第2张 -> 第二屏+第三屏（顺序判定）| 一1 二1 三1 四1
```

可以直接对着界面核对。

## 八、面板功能

| 控件 | 作用 |
|---|---|
| 开始 / 停止 | 开关监听（关窗口即停，不留后台进程） |
| 撤回上一步 | 文本(新建行)→删整行；文本(写空行)→只清空字段保留行；图片→只删那一张。**会同时取消还在排队/上传中的同内容任务** |
| 清空剪贴板 + 去重记忆 | 上次没传好想重来时，复制同样内容不会被当成重复跳过 |
| 清理本地图片缓存 | 显示 tmp/ unmatched/ pending/ logs 各占多少，可一键清理（队列里还在用的图自动跳过） |
| 测试图片 | 选一张图，看每条规则的命中情况和最终屏位 |
| 打开当前行 | 浏览器打开当前锁定的飞书记录 |
| 测试飞书连接 | 自检：取 token + 读表格，失败时直接告诉你要开哪个权限 |
| 复制日志 | 把日志区内容复制到剪贴板（会自动排除，不会被监听当成店名） |
| 设置 | 凭据 / 表格链接（粘贴自动解析）/ 字段映射 / 默认值 / 并发 / 规则。**打开设置会自动暂停监听**，避免复制的 Secret 被当成店名 |
| 下一张强制为 | 顺序判定偶尔串屏时，手动指定下一张图进哪一屏（只生效一次） |

窗口大小和位置会自动记忆。程序自带「编辑」菜单，⌘C / ⌘V / ⌘A / ⌘Z / ⌘Q 都可用。

## 九、屏位判定规则怎么改

规则全在 `config.yaml` 的 `rules:` 和 `flow:` 两段，`config.example.yaml` 里每一条都有注释。

几条设计原则（改之前最好知道）：

- **第四屏规则要排在第二/三屏之前**，否则带「座区」字样的页会先被第三屏吃掉。
- **`flow.fourth_markers` 里不能只写「外设」**：普通设备页几乎都有"鼠标… 外设 游戏特权"
  这行字，写裸词会让每张设备页都被当成"像第四屏"，兜底守卫直接失效。
- 判定是**按顺序逐条匹配，命中即停**，所以顺序敏感。
- 改完可以跑回归测试验证：
  ```bash
  python3 test_rules.py
  ```

## 十二、排障

| 现象 | 原因 / 处理 |
|---|---|
| 截图后没反应 | PixPin「复制图像为文件」设成了具体格式 → 改成「禁用」；或确认图真的进了剪贴板 |
| `99991672` 应用未开通权限 | 权限开了但**没发版本** → 版本管理与发布 → 创建版本 → 申请发布 |
| `1254005 / 1254006` | 多维表格没把该应用加为**可编辑**协作者 |
| `1254045` FieldNameNotFound | 字段名/字段 ID 映射不对 → 面板设置里检查字段映射 |
| 写入落到随机一行 | `feishu.view_id` 没填或填错（大小写敏感） |
| 一直"未识别" | 看 `ocr.cpu_only` 是不是被改成了 `true`；或截图只截到一半没有关键词 |
| 某屏位少一张图 | 看日志里有没有红色失败行。上传失败会保留在待传队列，重启面板自动补传 |
| 撤回后图又冒出来 | 已修复（撤回会取消排队/上传中的任务）。若仍出现，检查是否运行的是旧版本 |
| OCR 报 `e5rtError` | 神经网络引擎瞬时争用，程序会自动换新进程重试 |
| 想换台电脑用 | 整包拷贝 + 装依赖即可；飞书权限跟应用走，不用重配。两台电脑**别同时监听同一张表** |

## 十三、隐私与安全

- **截图内容不出本机做 OCR**：识别用的是 macOS 内置 Vision，完全离线。
- 图片最终上传到**你自己的**飞书多维表格。
- `config.yaml` 含 App Secret 和你的表格地址，**已在 `.gitignore` 中，不会进 Git**。
  仓库里只有脱敏的 `config.example.yaml`。
- 上传到 GitHub 前，建议确认这些目录没被提交：`config.yaml`、`.cache/`、`state.json`、
  `queue.json`、`logs/`、`tmp/`、`unmatched/`、`pending/`、`versions/`。
  ```bash
  git status --short        # 确认没有上面这些文件
  ```

## 十四、已知边界

- 只支持 macOS。
- 依赖"文本建行 → 图片归位"的约定：不复制店名直接截图，图会挂到 `pending/` 等店名。
- 同一张表**不要两台电脑同时监听**（会互相抢行）。
- 飞书 API 单次往返约 2.5~3s，所以一张图上传耗时 3~15s 是正常范围，不是卡死。
- 同一个图片文件不能同时占同一行的两个单元格（飞书限制），所以"第二屏+第三屏都写"
  是靠上传两份独立副本实现的。

## 十六、推送到 GitHub（自己维护仓库）

仓库推送走 **SSH**（`git@github.com`），不需要把 token 写进任何文件。

```bash
./push_github.sh                    # 推到 jamesyasin/clipboard-sync
./push_github.sh 别的仓库名          # 推到指定仓库
GITHUB_USER=你的账号 ./push_github.sh # 换账号
```

脚本会先做三件事再推：SSH 连通性检查 → 远端仓库是否存在 → **敏感信息自检**
